# v3 breaking changes and fork migration notes

> [!NOTE]
> These notes describe the breaking changes introduced in **v3.x.x** of the base app and assume the fork is on the **latest v2 release**. Forks on v1 also need to review the [v2 notes](v2.md) and any earlier changes missing from their source.

The runtime and styling changes were released in [v3.0.0](../../CHANGELOG.md#300--2026-09-07). [v3.1.0](../../CHANGELOG.md#310--2026-09-21) adds migration requirements for forks with custom Angular code or additional icons.

Paths and commands below refer to the v3 source layout. The [fork update workflow](../DEPLOYMENT.md#updating-from-the-base-app-digital-edition-frontend-ng) brings in the current upstream `main`. Review the relevant [breaking changes documents](README.md) and use the target version's runtime requirements, file layout, and commands when merging newer releases.

## 1. Update Node, npm, and build infrastructure

v3 requires Node.js `^24.15.0` and npm `>=11.16.0`. A Node 20/22 environment supported by v2 no longer meets these requirements.

Update local development, CI, and Docker build images. Merge upstream `package.json` and `package-lock.json` changes, including runtime declarations and npm install-script approvals, while preserving the edition's package identity and custom scripts. Install with `npm ci` using the supported runtime.

Adopt the upstream TypeScript/build changes accompanying Angular 22 and Ionic 9. Browser support now follows the Angular major version; check that the edition's browser requirements fit the target release's supported browsers.

## 2. Review changed home-page defaults

v3.0.0 changes these visual defaults:

| Area | Previous default | v3 default |
| --- | --- | --- |
| Site presentation in landscape mode. | Center-aligned text. | Start-aligned text. |
| Banner title and subtitle background. | Main background color at `0.8` opacity. | Transparent background at full opacity. |
| Text content width and placement. | Main sections up to `1000px` wide. | Centered content column up to `750px` wide. |
| Site title, subtitle, and footer in portrait mode. | Start-aligned. | Centered. |
| Search bar in wide portrait mode. | Start-aligned. | Centered. |

Review the edition at narrow and wide viewport widths in both orientations. Adjust the defaults in `src/assets/custom_css/custom.scss` using its CSS variable reference. For example, these overrides restore the earlier banner background/opacity and widen the content column:

```scss
page-home {
  --banner-title-background-color: var(--main-background-color);
  --banner-title-opacity: 0.8;
  --text-content-max-width: 1000px;
}
```

Alignment and spacing may need separate overrides to restore the edition's layout.

## 3. Move customizations out of removed scoped-variable partials

If the fork edited or imported any of these removed partials under `src/theme/scoped-variables/`, migrate those customizations:

| Removed partial | Affected area |
| --- | --- |
| `_info-overlay-variables.scss` | Info overlays. |
| `_page-elastic-search-variables.scss` | Elastic search. |
| `_page-index-variables.scss` | Indices. |
| `_page-text-variables.scss` | Text variants. |
| `_semantic-code-variables.scss` | Semantic highlighting. |
| `_text-changer-variables.scss` | Text changer. |
| `_top-menu-variables.scss` | Top menu. |

Move changed CSS custom property values into `src/assets/custom_css/custom.scss` under the selector listed in its override reference, and remove imports of the deleted partials.

## 4. Adapt customizations for v3.1

**v3.1.0** moves to standalone Angular/Ionic APIs and zoneless change detection. The bootstrap, component, and test guidance below applies to forks with custom Angular code. Forks using additional named icons also need the registration step.

### Bootstrap, providers, and routes

Application-owned NgModules are removed. Move fork-owned providers and routes to their replacement files:

| Previous customization location | v3.1 destination |
| --- | --- |
| Browser/shared providers in `src/app/app.module.ts`. | `src/app/app.config.ts`. |
| Server providers in `src/app/app.server.module.ts`. | `src/app/app.config.server.ts`. |
| Route registration in `src/app/app-routing.module.ts`. | The router providers in `app.config.ts` and canonical `src/app/app.routes.ts`. |
| Lazy page NgModules and their routing modules. | Standalone page components with `loadComponent`, or standalone `Routes` arrays with `loadChildren` where multiple/child routes are needed. |

Reconcile custom bootstrap code with `bootstrapApplication()` in `src/main.ts` and `src/main.server.ts`. Keep custom routes in `src/app/app.routes.ts` and regenerate production routes with `npm run generate-routes`.

### Standalone components and Ionic imports

Fork components must declare their template dependencies in their own `imports`, including Angular directives/pipes, child components, and Ionic standalone components from `@ionic/angular/standalone`. Remove custom components from NgModule `declarations` and update tests to import them into TestBed.

### Zoneless state and tests

Zone.js is removed. Custom code that relied on timers, promise callbacks, or manual DOM callbacks automatically triggering a render must notify Angular of template-state changes.

Use signals, the `async` pipe, or explicit Angular change-detection notification for asynchronous state. `NgZone.run()` no longer makes a template update by itself.

Remove custom `zone.js/testing` imports and replace Zone.js-based timing helpers with explicit asynchronous waiting or the target runner's timers.

### Register custom icons centrally

Import every additional named fork icon in `src/ionicons-polyfill.ts` and include it in the file's `addIcons()` call, preserving the names used by templates and configuration. Component-constructor registration is too late for icons present in server-rendered HTML.

See [icon registration](../DEVELOPMENT.md#registering-icons) for the convention.

## 5. Account for HTTP 404 on unknown routes

v3.1.0 returns HTTP **404** when Angular renders the page-not-found wildcard route. Update any tests, monitors, or custom middleware that expected HTTP 200 for these responses.

## 6. Validate the affected behavior

Use the commands of the target source. Check these migration-specific points:

1. Confirm the Node/npm versions, install with `npm ci`, run `npm run test:ci`, and build with `npm run build:ssr`.
2. Review home-page alignment, banner backgrounds, content width, and any migrated scoped overrides.
3. If the fork has custom Angular code, check its routes and asynchronous UI updates, including after returning to cached pages.
4. Check additional named icons on a direct SSR page load and after browser navigation. Verify HTTP 404 for unknown routes.
