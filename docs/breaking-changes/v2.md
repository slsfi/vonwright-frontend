# v2 breaking changes and fork migration notes

> [!NOTE]
> These notes describe the breaking changes introduced in **v2.x.x** of the base app and assume the fork is on the **latest v1 release**. Earlier v1 changes are outside this document's scope; forks on older v1 versions also need to review the [changelog](../../CHANGELOG.md).

The main breaking changes were released in [v2.0.0](../../CHANGELOG.md#200--2025-08-05). Required adaptations from later v2 releases are listed separately below.

Paths and commands in this document refer to the v2 source layout. The [fork update workflow](../DEPLOYMENT.md#updating-from-the-base-app-digital-edition-frontend-ng) syncs with the current upstream `main`. Review the relevant [breaking changes documents](README.md) and use the target version's runtime requirements, file layout, and commands when merging newer releases.

## 1. Update the runtime and merge dependencies

v2.0.0 drops Node.js 18 support. Its supported range is `^20.19.0 || ^22.12.0 || ^24.0.0`, and the supplied build infrastructure moves to Node 22. Update local development, Docker build images, and custom CI accordingly.

Adopt the Angular 20 and Express 5 dependency changes in `package.json` and `package-lock.json` together, preserving the edition's package identity and custom scripts. Browser support changes with Angular 20; review any browsers the edition previously supported outside that range.

If the fork customized root `server.ts`, merge the Express 5-compatible middleware changes; old wildcard registrations such as `server.get('*', ...)` are no longer valid.

If custom bootstrap or test code imports the removed `@angular/platform-browser-dynamic` package, adopt the `@angular/platform-browser` APIs used by the upstream source.

## 2. Merge the Sass inclusion changes

The shared stylesheet structure changes from Sass `@import` to `@use` and `meta.load-css()`. Forks that commented out imports in `src/global.scss` must reapply their selections to the new structure instead of retaining the old file wholesale.

| Customization | v2 location and mechanism |
| --- | --- |
| Select bundled fonts. | `src/global.scss`: comment out unused `meta.load-css()` calls. |
| Select individual TEI features. | `src/theme/_inc-global-tei.scss`: comment out unused `@use` lines. |
| Select info-overlay and tooltip styles. | `src/theme/_inc-global-optional.scss`: comment out unused `@use` lines. |

For example, font selection in `src/global.scss` becomes:

```scss
@use "sass:meta";

@include meta.load-css("theme/font-face/source-serif");
// @include meta.load-css("theme/font-face/inter");
```

Reapply the edition's font and feature selections to the new includes. If the fork has custom Sass partials, declare their `@use` dependencies rather than relying on variables shared through `@import`.

The `.teiComment.noteReference` rule is removed from `src/theme/TEI/_tei-comments.scss`. Editions that need the previous appearance of references after comment notes can add this rule to their `custom.scss`:

```scss
div.tei .teiComment.noteReference {
  display: block;
  font-size: 0.85em;
  line-height: 1.55;
  margin-top: 0.5em;
}
```

## 3. Reconcile navigation settings and branding

The separate home button, right-hand site logo, and "refer to edition" button are removed from the top menu. The linked site title replaces the home button; check `Site.Title` in the edition's translation files and review branding that depended on the logo.

Remove these obsolete configuration entries when merging `src/assets/config/config.ts`:

| Removed setting | v2 behavior and fork action |
| --- | --- |
| Logo settings under `component.topMenu`: `showSiteLogo`, `siteLogoDefaultImageURL`, `siteLogoMobileImageURL`, `siteLogoLinkURL`, `siteLogoDimensions` | Right-hand logo removed. |
| `component.topMenu.showURNButton` | Top-menu reference button removed. |
| `component.mainSideMenu.items.home` | Home is always present in the main side menu. |
| `component.epub` | The integrated EPUB viewer and its controls are removed. |

## 4. Remove EPUB-viewer links

The integrated EPUB viewer is removed. Remove EPUB-viewer entries from the edition's `ebooks` configuration and menu links. Offer EPUB files through ordinary download links or download options instead of the removed viewer.

## 5. Apply later v2 compatibility changes

These later changes affect build configuration or deployment:

| Release | Change and fork action |
| --- | --- |
| [v2.2.2](../../CHANGELOG.md#222--2025-11-11) | The base `extra_hosts` entry is removed from `compose.yml`. If the deployment relied on it, retain the required host mapping. |
| [v2.5.0](../../CHANGELOG.md#250--2026-02-20) | Merge the `generate-routes` build step and production route-file replacement. The generated file is required even when feature filtering is disabled. Keep any custom routes in `src/app/app.routes.ts`, not the generated file. |
| [v2.5.1](../../CHANGELOG.md#251--2026-02-27) | SSR adds host validation. Check that `app.siteURLOrigin` contains the edition's public origin so its hostname is allowed. |
| [v2.6.0](../../CHANGELOG.md#260--2026-03-12) | `ng-extract-i18n-merge` moves to v3. Remove `projects.app.architect.extract-i18n.configurations` from `angular.json`, retain the edition's translation targets, and merge the extraction options. |
| [v2.6.0](../../CHANGELOG.md#260--2026-03-12) | Dynamic SSR requests are now rate-limited. Review `app.ssr.trustProxyHops` (default `2`) for the deployment's proxy chain so limits apply to the correct client IP. |

Only forks with the following customizations need these additional adaptations:

- **Custom Angular code or specs:** [v2.2.0](../../CHANGELOG.md#220--2025-09-19) and later refactors introduce signal inputs/queries and `output()`. Read signals by calling them and replace assignments to readonly inputs. [v2.7.7](../../CHANGELOG.md#277--2026-08-11) removes `@angular/animations`; review custom imports of that package.
- **Authentication already enabled:** [v2.7.0](../../CHANGELOG.md#270--2026-05-22) requires startup and refreshed tokens to pass backend `/session/validate` before use. Verify that backend contract and login/session behavior; see [authentication](../AUTHENTICATION.md).

## 6. Validate the edition after merging

For a later v2 checkout:

1. Run `npm ci` and `npm run extract-i18n`; review the translation diff. Run the available unit tests if the fork changed application code or specs.
2. Run `npm run generate-routes`, `npm run build:ssr`, and `npm run serve:ssr`; check the edition's production routes and locales.
3. Check font/TEI selections, overlays/tooltips, and comment-reference styling after the Sass merge.
4. Review menu branding and home/reference controls, and confirm EPUB files use download links rather than viewer routes.
5. Verify SSR through the deployment's proxy chain. If auth is enabled, check token/session validation.
